## Рывок

`POST /survivors/{id}/sprint` без тела запроса расходует 40 единиц стамины.
Успешный рывок возвращает `204`. Если выживший погиб или стамины меньше 40,
сервер возвращает `409`. Для отсутствующего выжившего сервер возвращает `404`.

`GET /survivors/{id}` показывает текущую стамину в поле `stamina`.
Энергетик восстанавливает 30 единиц стамины, максимум до 100.

## Фильтрация предметов

`GET /items?type=medkit` или `GET /items?type=energyDrink` возвращает предметы указанного типа.
Порядок параметров и регистр значения `type` не важны. Без `type` возвращаются все предметы.
Неизвестный тип даёт пустой список. Пустой или повторяющийся параметр `type` даёт `400`.

## Размер JSON-запроса

Маршруты, которые читают JSON из тела запроса, принимают до 16 КиБ (16 384 байта) включительно.
Если тело больше, сервер возвращает `413` до разбора JSON.

## ID ресурсов

`POST /survivors` и `POST /items` возвращают `{"id": ...}` при создании ресурса.
Этот же числовой `id` присутствует в ответах `GET` для отдельного ресурса и у каждого объекта в списках, включая отфильтрованные.

## Фильтрация выживших

`GET /survivors?alive=true` возвращает живых выживших, а `alive=false` возвращает погибших.
Без `alive` список включает выживших с любым здоровьем.
`name` ищет по части имени без учёта регистра. Если передать оба параметра, запись должна подходить под оба фильтра.
Пустое, неизвестное или повторяющееся значение `alive` возвращает `400`.
