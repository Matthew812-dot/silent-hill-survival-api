# Silent Hill Survival HTTP API

Лабораторная: Java, Maven, JDK HttpServer и Jackson. Предметная область — выжившие, расходуемые предметы и инвентарь в Silent Hill.

## Запуск и проверка

Нужны JDK 25 и Maven 3.9+. В IntelliJ открыть pom.xml и выбрать JDK 25.

```sh
mvn clean verify
mvn exec:java
```

Сервер: http://localhost:8080. Данные хранятся в памяти и исчезают после перезапуска. Для примеров запустить `bash requests.sh` (Git Bash); сценарий сам получает ID и проверяет ожидаемые HTTP-коды. В PowerShell для JSON удобно использовать `'{"name":"James"}' | curl.exe -i http://localhost:8080/survivors -H 'Content-Type: application/json' --data-binary '@-'`.

## API

Все тела запросов и ответов — JSON. ID положительные целые, выдаются сервером. Создание возвращает 201, объект с ID и Location; удаление — 204 без тела.

| Метод | Путь | Данные / результат |
|---|---|---|
| GET | /ping | Проверка сервера |
| GET | /survivors | Список; фильтры name (подстрока без учёта регистра), alive=true/false |
| POST | /survivors | {"name":"James"}; health и stamina изначально 100 |
| GET | /survivors/{id} | Один выживший |
| PUT | /survivors/{id} | Полная замена состояния: {"name":"James","health":60,"stamina":50} |
| DELETE | /survivors/{id} | Удаление выжившего вместе с принадлежащими ему предметами |
| GET | /items | Список; фильтр type=Medkit или EnergyDrink |
| POST | /items | {"type":"Medkit"} или {"type":"EnergyDrink"} |
| GET | /items/{id} | Один предмет |
| PUT | /items/{id} | Замена типа, например {"type":"EnergyDrink"}; ID и владелец сохраняются |
| DELETE | /items/{id} | Удаление предмета, включая ссылку из инвентаря |
| GET | /survivors/{id}/inventory | Содержимое инвентаря |
| POST | /survivors/{id}/inventory | {"itemId":1}; предмет может принадлежать только одному выжившему |
| POST | /survivors/{id}/inventory/{itemId}/use | Использование предмета без тела запроса |
| POST | /survivors/{id}/damage | {"amount":60}; положительный урон |

Medkit восстанавливает 40 здоровья, EnergyDrink — 30 выносливости. Значения ограничены диапазоном 0–100. После использования предмет удаляется из инвентаря и каталога. Фильтры можно сочетать: `/survivors?name=jam&alive=true`.

Ошибки имеют вид `{"error":"описание"}`: 400 — некорректные данные/JSON/ID, 404 — ресурс или маршрут отсутствует, 405 — метод не поддерживается (с Allow), 409 — конфликт принадлежности предмета. Невалидное обновление не меняет состояние.

## Устройство и тесты

Survivor хранит состояние персонажа. Абстрактный Item и реализации Medkit/EnergyDrink задают поведение предметов. SurvivalService хранит сущности и инвентари; SurvivorHandler маршрутизирует запросы, проверяет JSON и формирует ответы. Main запускает HttpServer.

`mvn test-compile exec:java -Dexec.mainClass=app.ApiChecks -Dexec.classpathScope=test` (или `./check.ps1` в PowerShell) выполняет три интеграционных сценария без сторонних тестовых библиотек через настоящий HTTP-сервер на свободном порту: жизненный цикл и расходование предмета; ошибки и неизменность состояния при неудачном обновлении; CRUD предметов, фильтрация и очистка инвентаря. Тесты независимы, сервер останавливается после каждого сценария.

Зависимости приложения: только Jackson; HTTP, коллекции и HTTP-проверки используют стандартную библиотеку JDK. mvn verify собирает проект; интеграционные проверки запускаются отдельной командой выше.


Защита обработчика: тело JSON ограничено 64 КиБ (413 при превышении), время приёма запроса и отправки ответа ограничено настройками JDK HttpServer в 10 секунд. Запросы обслуживаются отдельными виртуальными потоками; доступ к общему состоянию согласован.
